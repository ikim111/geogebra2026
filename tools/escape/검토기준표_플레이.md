# 방탈출 플레이 채점표 (48점)

새 회차를 만들거나 고칠 때마다 이 표로 채점한다. 항목마다 **2점(잘됨) / 1점(조금 고침) / 0점(고쳐야 함)**.
- **통과 기준**: A·B 영역은 모든 항목이 2점, 전체 85%(41점) 이상.
- **두 번 채점한다**: ① 만든 사람(Claude)이 직접, ② 답을 모르는 별도 검토자가 학생 4명(A 수학 잘함 / B 보통 / C 자주 헷갈림 / D 꼼수) 역할로 플레이 테스트.
- 채점 결과는 영역별 점수 표 + 깎인 이유 + 고칠 안으로 보고한다.
- 카드 생김새(글씨·그림·인쇄)는 따로 `검토기준표_카드디자인.md`로 본다.

## 근거
- 방탈출 설계 평가: Nicholson의 방탈출 설계 기준, Room2Educ8 프레임워크, Veldkamp(2022) 교육용 방탈출 설계 원칙
- 퍼즐 설계: eCampusOntario Escape Room Guide, Sherlocked "How escape rooms are designed"
- Unlock! 리뷰(Meeple Mountain): 숨은 정보 과다, 한 줄 진행 시 노는 학생, 이야기와 안 맞는 퍼즐
- 재미: **GameFlow 모델**(Sweetser & Wyeth, 2005, 플로우 이론 바탕: 집중·알맞은 도전·실력이 느는 느낌·조종감·분명한 목표·즉시 피드백·빠져듦·상호작용), **MDA 틀**(Hunicke 외, 2004: 이야기·도전·발견·협동 등 재미의 종류, 방탈출은 발견과 협동이 핵심)

## A. 수학 학습 (8점)
| # | 기준 | 확인 방법 |
|---|---|---|
| A1 | 문제마다 그 회차의 수학을 **써야만** 풀린다. 찍기·가운데쯤 누르기·큰 것 고르기로 맞힐 수 없다 | 문제마다 "수학 없이 풀 수 있나?" 따져 보기, 무작위 시도 비용 |
| A2 | 수학이 맞고 답이 **하나뿐**이다 | 직접 계산, 기계는 프로그램으로 모든 입력 시험 |
| A3 | 교과서 용어를 쓰고 **배운 범위 안**이다(중2 범위 밖 도구 금지, 예: 기울기) | 교과서·진도와 대조 |
| A4 | 흔한 오개념을 함정 카드·오답 안내로 다룬다 | 오답마다 이유가 나오는지 |

## B. 공정성·명확성 (12점)
| # | 기준 | 확인 방법 |
|---|---|---|
| B1 | 푸는 데 필요한 정보가 **제때** 카드에 다 있다(조건 빠짐·늦게 나옴 없음) | 카드만 보고 처음부터 풀어 보기 |
| B2 | 문장이 한 가지로만 읽힌다(모둠 인원, "차례로", "걸음" 등) | 다르게 읽힐 말 찾기 |
| B3 | 답 형식이 분명하다(자리 수, 앞 0, 단위, 순서, 기약분수) | 자물쇠·기계 카드 문장 |
| B4 | 그림·도형이 비율에 맞고 착각을 부르지 않는다 | 실제 값으로 다시 그려 보기 |
| B5 | 숨은 번호는 회차당 1~2개, 쓰임이 있고 🔍로 찾을 수 있다(쓸모없는 숨은 숫자 없음) | 숨은 번호 위치·쓰임 |
| B6 | 논리 비약이 없다. 구한 값이 다음 단계에 **실제로 쓰인다** | 단계마다 이유 말해 보기 |

## C. Unlock! 방식 (6점)
| # | 기준 | 확인 방법 |
|---|---|---|
| C1 | 카드 색 = 종류, 번호 모양, 오른쪽 위 아이콘(⚙️🔒⏳), 금지어 없음, 마지막 카드는 "🏁 탈출에 이 번호를" | PDF·`audit.js` |
| C2 | 카드의 버리기 표시 = 화면의 치우기, 벌점 카드는 자기만 버림 | `check_round.py` |
| C3 | 뜻밖의 빨강+파랑 합이 없고, 남은 카드가 엉뚱하게 다시 합쳐지지 않는다 | `check_round.py` |

## D. 흐름·협력 (6점)
| # | 기준 | 확인 방법 |
|---|---|---|
| D1 | 장면마다 갈래가 2개 이상이라 4~5명이 **동시에** 할 일이 있다 | 장면마다 동시에 풀 문제 수, 노는 학생 |
| D2 | 45분 분량: 문제 7~8개, 카드 30~40장, 보통 모둠 35~45분 | 플레이 테스트 시간 추정 |
| D3 | 버리기 표시대로 해도 모든 카드에 닿고 끝까지 간다. 쉬운 것 → 어려운 것 | `check_round.py`, 문제 순서 |

## E. 이야기 (6점)
| # | 기준 | 확인 방법 |
|---|---|---|
| E1 | 퍼즐마다 이야기 속 이유가 있다("왜 이걸 해야 해?"가 없음) | 한 줄로 이유 말해 보기 |
| E2 | 회차 사이가 이어진다(앞 회 마지막 → 이번 시작) | 앞 회 마지막 카드와 이번 시작 카드 |
| E3 | 반전·숨은 이야기는 몰라도 진행에 지장 없고, 복선이 앞 회에 실제로 있다 | 반전 카드와 앞 회 카드·그림 |

## F. 재미 (10점)
| # | 기준 | 확인 방법 |
|---|---|---|
| F1 | **퍼즐마다 '아하' 순간이 있다.** 그냥 계산이 아니라 "아, 그래서 외심이구나!"처럼 깨닫는 순간 | 퍼즐마다 깨닫는 문장을 적어 보기. 계산만 있으면 감점 |
| F2 | **같은 유형이 연달아 나오지 않는다.** 숫자 넣기만 이어지지 않는다 | 퍼즐 유형 순서. 같은 유형은 2번까지만 연속 |
| F3 | **놀람과 보상이 있다.** 카드를 뒤집으면 예상 못 한 것(새 장소, 반전, 보상)이 나온다 | 펼친 카드 중 놀람·보상 비율 |
| F4 | **손으로 하는 재미가 있다.** 카드 뒤지기, 숨은 번호 찾기, 다이얼 돌리기 | 화면 입력만 하는 단계가 얼마나 되는지 |
| F5 | **말을 해야 풀린다.** 단서가 여러 카드에 흩어져 있어 모둠이 대화한다 | 카드 하나로 혼자 끝나는 퍼즐 수 |

- 설계에 들어 있는지는 시뮬레이션으로 확인한다. **실제 재미**는 학생이 해 봐야 안다 → 끝나고 3문항 설문: "재미있었다", "또 하고 싶다", "어려웠던 곳은?" 결과로 다음 회차를 고친다.
